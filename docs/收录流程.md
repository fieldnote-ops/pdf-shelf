# 收录流程

PDF 不进 git。仓库只存目录、元数据与说明；PDF 作为 Release 资产分发，下载链接写进 catalog。

## 新增一本

1. 确认 PDF 是自己编写或有权公开发布的材料。
2. 登记元数据（会生成 README 表格与 `SHA256SUMS`）：

```bash
python3 scripts/add_pdf.py \
  --file ~/Work/docs/output/pdf/xxx.pdf \
  --id system-atlas \
  --series 从内核到智能体 \
  --title "从内核到智能体：系统原理解剖图解全集" \
  --version 2026.12 \
  --status complete \
  --source "Typst 0.15.1 / docs 仓库"
```

`--dry-run` 只打印条目；`--mirror <https 地址>` 可加备用下载源；`--repo owner/repo` 在 remote 缺失时指定仓库。

资产文件名默认 `<id>-<版本>.pdf`，**必须是 ASCII**——GitHub 会把非 ASCII 字符替换成 `-`，导致链接对不上。

3. 校验并提交：

```bash
python3 scripts/check_repo.py
git add -A
git commit -m "feat: 收录《书名》2026.12"
git push
```

4. 打 tag、发 Release、上传 PDF：

```bash
git tag -a v2026.12 -m "《书名》2026.12"
git push origin v2026.12
gh release create v2026.12 --verify-tag --title "..." --notes "..."
cp "本地文件.pdf" "system-atlas-2026.12.pdf"
gh release upload v2026.12 "system-atlas-2026.12.pdf"
```

如果 Release 已存在（例如重传），加 `--upload` 让脚本代传：

```bash
python3 scripts/add_pdf.py ... --upload
```

5. 实际下载一次，确认资产可用：

```bash
scripts/fetch.sh <id> /tmp/shelf-check
```

## 约定

- **版本号** `YYYY.MM`，tag 为 `vYYYY.MM`，资产文件名 `<书名>-YYYY.MM.pdf`。
- **PDF 不覆盖**：换版用新版本号与新资产；旧 tag 与旧 Release 原样保留。
- **id 稳定**：ASCII 小写串，换版不变；下载用 id 或 tag，不用文件名。
- **体积**：Release 单资产上限 2 GB；超过 100 MB 会告警，建议拆分或换托管。
- **变更记录**：每次新增/换版在 `CHANGELOG.md` 记一行。

## 换版

同一 `id` 加 `--replace`，指向新版本号与新 tag：

```bash
python3 scripts/add_pdf.py --file ~/Work/docs/output/pdf/新全集.pdf \
  --id system-atlas --version 2026.12 --replace
```

随后提交、打 `v2026.12`、发 Release、上传新资产。旧版仍在 `v2026.11` 的 Release 里。

## 离线校验做什么

`scripts/check_repo.py` 只检查：

- catalog 字段完整、id/filename/URL 不重复；
- 下载地址是本仓库的 Release 资产，且 tag/文件名与字段一致；
- README 表格含该地址；
- `SHA256SUMS` 与 catalog 的哈希集合一致。

它**不下载 PDF、不访问网络**。资产是否真的可下载，靠发版后跑一次 `fetch.sh`。

## 目录结构

```
catalog.yaml           # 唯一事实来源（下载地址、哈希、页数、状态）
README.md              # 收录表由脚本生成
SHA256SUMS             # 由脚本生成
pdfs/<系列>/README.md   # 分册说明，不含二进制
docs/                  # 流程与现状
scripts/               # 登记、离线校验、断点续传下载
```
