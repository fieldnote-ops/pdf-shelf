# 收录流程

书架的变更都走 `scripts/add_pdf.py`：复制文件、读元数据、写 `catalog.yaml`、重生成 README 表格。手改 README 表格会在下次运行时被覆盖；手改 catalog 容易和文件失配。

## 新增一本

1. 确认 PDF 是自己编写或有权公开发布的材料。
2. 入库：

```bash
python3 scripts/add_pdf.py \
  --file ~/Work/docs/output/pdf/xxx.pdf \
  --id system-atlas \
  --series 从内核到智能体 \
  --title "从内核到智能体：系统原理解剖图解全集" \
  --version 2026.11 \
  --filename 从内核到智能体-系统原理解剖图解全集-2026.11.pdf \
  --status partial \
  --status-note "第七篇「完整嵌入式系统」尚未整合完整，详见 docs/嵌入式现状.md" \
  --source "Typst 0.15.1 / docs 仓库"
```

- `--dry-run` 只打印条目，不写文件。
- `--status` 取 `complete` / `partial` / `draft`；只要不是 `complete`，就写 `--status-note`。
- `--source` 记构建工具与来源仓库，方便日后回溯。

3. 校验并提交：

```bash
python3 scripts/check_repo.py
git add -A
git commit -m "feat: 收录《书名》"
git push
```

CI 会在 push 后重跑同一份校验。

## 约定

- **版本号** `YYYY.MM`，与书内版本日期一致；文件名带版本号，如 `-2026.11.pdf`。
- **不覆盖已发布文件**：换版用新文件名，旧文件先归档再删除。
- **id 稳定**：ASCII 小写串，换版不变；外部引用优先用 id 或 tag，而不是文件名。
- **体积**：脚本 100 MB 硬失败、50 MB 告警。更大的文件改用 GitHub Releases 托管，仓库只留元数据。
- **变更记录**：每次新增或换版在 `CHANGELOG.md` 记一行。

## 换版

同一 `id` 加 `--replace`，脚本会替换旧条目并删除旧文件（工作区变化，`git add -A` 时才会暂存删除）：

```bash
python3 scripts/add_pdf.py --file ~/Work/docs/output/pdf/新全集.pdf \
  --id system-atlas --version 2026.12 \
  --filename 从内核到智能体-系统原理解剖图解全集-2026.12.pdf \
  --replace
```

旧版不要留在 git 历史里，挂到对应 tag 的 Release：

```bash
gh release upload v2026.11 "旧全集.pdf"
```

## 目录结构

```
catalog.yaml           # 唯一事实来源
README.md              # 收录表由脚本生成（<!-- catalog:begin --> 之间）
pdfs/<系列>/            # 每册一个目录，含分册 README
docs/                  # 流程与现状说明
scripts/               # 收录与校验
```
